# Что отображается и как это работает (после перехода на форму)

Краткий гид по экрану сервера: что значат вкладки, цифры и откуда они берутся.

---

## Вкладки сверху

### **RAW** — сырые сигналы и спектры

- **Что рисуется:** осциллограммы X, Y, Z (акселерометр ADXL355) и ADS (если есть) по времени; под ними FFT-спектры по каждому каналу (0.2 Гц – Fs/2).
- **Откуда данные:** буфер `g.buf` (adxlX, adxlY, adxlZ, ads). Окно по времени задаётся слайдером **t:** (50 ms – 5 s).
- **Слайдеры над графиками:**
  - **t:** — длина временного окна (мс).
  - **Y:** — масштаб по вертикали: Auto (по данным) или множитель вручную.
  - **FFT:** — размер FFT (512 / 1024 / 2048 / 4096).
- **Смысл:** смотреть «как есть» — уровень сигнала, шум, наличие тонов. Никакой токенизации и паттернов здесь нет.

---

### **ПОЛОСЫ** — разбор по частотным диапазонам (SDR-стиль)

- **Что рисуется:** заголовок filterbank, сетка полос B0..B7 (логарифмическая сетка по Гц), краткое описание каждой полосы и подсказка по семантике.
- **Полосы (каналы наблюдения):**
  - **B0:** 0.2 – 2 Hz (медленная модуляция / дрейф)
  - **B1:** 2 – 10 Hz (огибающая, ритм)
  - **B2:** 10 – 40 Hz (механические колебания)
  - **B3:** 40 – 120 Hz (структурные резонансы)
  - **B4:** 120 – 400 Hz (возбуждение / удары)
  - **B5:** 400 – 1.5 kHz (гребёнки, контакт)
  - **B6:** 1.5 – 5 kHz (несущая + искажения)
  - **B7:** 5 – 20 kHz (микровибрации / шумовая подпись)
- **Смысл:** не «анализ волны», а разворот в параллельные временные реальности x(t) → {x_B0(t), …, x_B7(t)}. В каждой полосе далее: envelope, RMS, burst/hold/silence; глиф = событие в полосе. Сейчас на вкладке — только справочная сетка; реализация filterbank и событий по полосам — следующий шаг.

---

### **DISCOVERY** — первый алфавит (exciter, band)

Показывает **первый алфавит**: ячейки адреса (exciter_id, band_id). Статический, не ML.

**Сверху:**
- **Exciter** — текущий режим возбуждения (idle, am-sine, chirp, …).
- **Ячеек** — число активных ячеек в PrimaryAlphabetStore.
- **Bands** — B0..B7 без изменений.

**Сетка:**
- Строки: **idle** (exciter=0) и **текущий exciter** (из protocol.AutoPresetName).
- Столбцы: **B0..B7** (8 полос).
- В каждой ячейке: **E** (энергия), зелёный бар по высоте, `B%d E=%.3f`.
- Пустые ячейки — «B%d —».

**Как это работает:**
1. Pipeline каждые 250 ms считает энергию по полосам (bandSquared).
2. E_rel[b] = E[b] / (sum(E)+eps) — относительный порог.
3. Гистерезис: включить при E_rel > T_on (3%), выключить при E_rel < T_off (1.5%).
4. Затухание: при E_rel < T_off — decay 0.9, не обнуление.
5. Лимит: макс N_max (8) активных полос среди тех, кто выше порога.
6. exciter_id берётся из protocol.AutoPresetName (am-sine→1, chirp→2, …).

---

### **ALPHABET** (ранее LOCKED) — зафиксированные токены по форме

- **Lock settings** — кнопки **T_lock**, **Δf (bins)**, **ΔA (%)** — это **legacy** от старой частотной модели. В текущем пайплайне по форме они **не используются** (токены добавляются по совпадению формы, а не по hold частоты). Можно игнорировать или оставить для совместимости.
- **Сетка карточек** — это **токены (паттерны)** из PatternStore.
  - Каждая карточка: **глиф** (волна по форме: 64 точки в нормализованной фазе) + подпись **Pattern 01**, **Pattern 02**, … + при повторных совпадениях **x2**, **x3** (Occurrences).
  - Глиф рисуется из **GlyphShape.Points** (новая модель) или из **GlyphData** (старый формат 32×min+32×max), если Shape нет.
- **Смысл:** «алфавит» узнанных форм. Один и тот же токен может встречаться при разных частотах и мощностях — важен только форма. Частота/амплитуда хранятся как метаданные (FreqRangeHz, AmpRange), но не как ключ.

**Как токен попадает в LOCKED:**
- В пайплайне (DISCOVERY) из текущего окна строится форма и кластеризуется. Если центроид кластера **не совпадает** ни с одним существующим токеном по ShapeDistance &lt; порог, создаётся **новый** паттерн (новый ID) и добавляется в PatternStore. При совпадении формы — **merge**: обновляются только Occurrences, LastSeenTs, Confidence, диапазоны частот/амплитуд; глиф не меняется.

#### Графики глифов на ALPHABET: общий и по осям

**Что отображается:**

- **Режим Combined (общий):**
  - Если есть **GlyphShape.Points** — одна кривая: фаза-нормализованная форма одного цикла (64 или 128 точек в памяти; на экране рисуется упрощённо).
  - Иначе **GlyphData** (ось X) — одна линия: середина envelope (среднее между min и max по 32 сегментам).
- **Режим 3 axes (по осям):**
  - Три кривые в одном поле: **X** (красный), **Y** (зелёный), **Z** (синий). Каждая — midline envelope своей оси (32 сегмента → одна полилиния по середине min/max).

**Откуда берутся данные (оригинал до упрощения):**

| Данные | Источник | Что это |
|--------|----------|--------|
| **Shape (GlyphShape)** | Окно по частоте пика: либо **bandSquared[полоса]** = xB²+yB²+zB² после bandpass по полосе B0..B7, либо **канал X** | Один цикл волны: экстремумы/нули → resample по фазе → 64 или 128 точек, нормализация в [-1, 1]. Фаза-нормализация = один и тот же глиф не зависит от сдвига по времени. |
| **GlyphData (X), GlyphDataY, GlyphDataZ** | **Тот же сегмент одного цикла**, что и профиль (Shape) | Границы цикла берутся из BuildShapeWithBounds (UseBands) или ExtractWaveShapeAtFreqWithBounds (без полос). Трёхосевой глиф = HD-версия профиля по осям: envelope X/Y/Z по тому же окну. I/Q демодуляция на f0 → LPF → envelope → 32 сегмента (min/max) → 64 точки, нормализация [-1, 1]. |

**Чем упрощено отображение (только для рисования, данные в паттерне полные):**

| Режим | Оригинал в памяти | Упрощение при отрисовке |
|-------|-------------------|--------------------------|
| Combined, Shape | 64–128 точек (GlyphShape.Points) | **Субсэмпл до 24 сегментов**: рисуется 24 отрезка вместо 63–127 — меньше линий, форма та же. |
| Combined, GlyphData | 64 точки (32 min + 32 max) | Рисуется **только midline** (среднее min/max по сегменту) — одна линия вместо верх/низ/середина. |
| 3 axes | 64 точки на ось (X, Y, Z) | По каждой оси рисуется **только midline** (одна линия на цвет). |

То есть: на экране показываются **те же актуальные** данные паттерна (GlyphShape, GlyphData, GlyphDataY, GlyphDataZ), но с упрощённой геометрией (меньше отрезков / только середина envelope), чтобы отрисовка была быстрой.

#### Почему «общий профиль» может кардинально отличаться при одинаковой картинке по осям

**Разные источники данных:**

| Что на экране | Откуда данные | Как считается |
|---------------|----------------|---------------|
| **Три оси (X/Y/Z)** | **bandX, bandY, bandZ** (каналы полосы) | **Envelope** по каждому каналу: в каждом из 32 фазовых бинов берётся min и max → нормализация в [-1,1]. Три кривые: «как высоко/низко идёт X», «Y», «Z» по фазе. |
| **Общий профиль (Combined)** | **bandSquared** = x²+y²+z² (энергия полосы) | **Один** скалярный сигнал. Один цикл → resample по фазе → **вычитание линейного тренда** (первая и последняя точка = 0) → нормализация в [-1,1]. |

То есть «три оси» — это **три envelope по X, Y, Z**; «общий профиль» — это **одна кривая из суммы квадратов** с вычитанием тренда. Это **разные величины**, не просто «сумма» осей.

**Почему форма так сильно расходится:**

- **bandSquared = X²+Y²+Z²** всегда неотрицателен. После **вычитания линейного тренда** (линия от первой до последней точки) кривая обязана начинаться и заканчиваться нулём — в середине могут быть и положительные, и отрицательные значения. Получается либо **одна горка**, либо **пик и впадина** (две лопасти), в зависимости от того, как выглядит сегмент bandSquared.
- Если **X, Y, Z в фазе** (пики совпадают по времени) — bandSquared даёт один острый пик → после тренда одна горка.
- Если **X, Y, Z не в фазе** (пики сдвинуты) — сумма квадратов **размазывается**: два горба или широкая платформа → после вычитания тренда получается **пик и впадина** (две лопасти), а не одна горка.
- При этом **envelope по X, Y, Z** по отдельности может по-прежнему выглядеть как «один импульс» на каждой оси: каждая ось даёт одну горку min/max по фазе. Визуально три оси выглядят одинаково, хотя **фазовая связь** между осями другая.

**Итог:** одна и та же «картинка с тремя осями» (похожие X/Y/Z) может соответствовать **совершенно разному** общему профилю (одна горка vs пик+впадина), потому что общий профиль строится из **bandSquared с вычитанием тренда**, а не из самих X,Y,Z. Разная фаза между осями даёт разную форму суммы квадратов → разный Shape.

**Что скармливается модели (TRAINER, MEANING):**

- В модель идут **полные** данные, без упрощения отрисовки:
  - **TrainerGlyphBuffer.Add(pts, bandIdx, nowMs)** — `pts = shape.Points` (полный массив 64 или 128 точек фаза-нормализованной формы).
  - **OnGlyphForMeaning(shape.Points, bandIdx)** — тот же `shape.Points` при каждом срабатывании пайплайна (инференс на вкладке MEANING).
- То есть в модель попадает **одна кривая** — **ShapeVector.Points** (общая форма по полосе или по X), **не** три отдельные оси X/Y/Z. Классификация и merge идут по форме (ShapeSignature, distance по Points); GlyphData X/Y/Z используются для отображения и кольца LastN в попапе.

## Общая схема потока данных

```
Буфер (X,Y,Z) → Preprocess (mag2/RMS, highpass) → s_norm
       ↓
BuildShape(s_norm) → ShapeVector (64 точки)
       ↓
ShapeClusterStore (один кандидат на окно) → кластеры
       ↓
ResidualDecomposer.Decompose(s_norm, PatternStore)
  → итерации: FindBestToken (cross-corr) → SubtractToken → H, ΔH, steps
       ↓
Центроиды кластеров → MergeOrAddByShape(PatternStore) → новые/обновлённые токены
       ↓
RAW: буфер + FFT  |  ПОЛОСЫ: сетка B0..B7 (filterbank)  |  DISCOVERY: H, steps, ΔH, кластеры  |  ALPHABET: токены (глифы)  |  TRAINER/MEANING: последовательности глифов
```

## Кратко по вкладкам

| Вкладка   | Что значит | Откуда данные |
|-----------|------------|----------------|
| **RAW**   | Сигнал и спектр «как есть» | Буфер, FFT по окну |
| **ПОЛОСЫ** | Разбор по частотным полосам (SDR): сетка B0..B7, каналы наблюдения | Справочная сетка (filterbank — следующий шаг) |
| **DISCOVERY** | Разложение по форме: энтропия остатка H, шаги ΔH, кластеры форм, график остатка | ShapeClusterStore, ResidualDecomposer (последний результат) |
| **ALPHABET** | Уже узнанные токены (глифы по форме), счётчик вхождений | PatternStore |

Токенизация идёт **только по форме** (нормализованная фаза цикла); частота и мощность — условия эксперимента и метаданные, не ось идентичности.
