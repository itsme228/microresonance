# Как работает алфавит глифов: критерии и порядок

Краткое описание: откуда берутся токены, по каким правилам они объединяются (merge) или создаются заново, как отображаются и когда удаляются.

---

## 1. Откуда берутся волны

1. **Сырой сигнал**: X, Y, Z с акселерометра (например 4000 Гц), окно ~2.5 с.
2. **FFT** по каждой оси → спектр, в нём ищем **пики** (локальные максимумы).
3. **Полосы B0…B7**: частоты разбиты на 8 полос (0.2–2 Гц, 2–10, 10–40, 40–120, 120–400, 400–1500, 1500–2500, 2500–5000 Гц). В каждой полосе берутся **до 3 сильнейших пиков** (всего до 24 пиков на тик).
4. **Фильтры**:
   - **ampNorm ≥ AmpNormThr** (по умолчанию 0.8) — только достаточно сильные пики;
   - **StationarityOK** (при `AllowAllWaves=false`): огибающая стационарна (CV и slope в пределах A_cv, A_slope);
   - **ShapeLooksCleanCycle** (при `AllowAllWaves=false`): форма «чистая» (число пересечений нуля и т.п.).
5. Для каждого прошедшего пика из **полосы** (band squared) извлекается **форма одного цикла** волны → 64–256 точек по фазе (PointsPerCycle), нормализация (median или RMS).

Итог: на каждый тик пайплайна в алфавит претендуют волны из полос B0…B7 с «хорошей» формой и достаточной амплитудой.

---

## 2. Критерии merge: когда волна попадает в существующий токен

Одна волна (форма + полоса + частота) либо **мержится** в уже существующий паттерн (токен), либо добавляется как **новый** токен.

### 2.1. Главный критерий — расстояние по форме

- **ShapeDistance** (косинусное или евклидово по нормализованной форме) между новой формой и **эталоном** паттерна (GlyphShape).
- **DistThr** (в интерфейсе «dist»): если расстояние **< DistThr**, форма считается той же — идёт **merge**, иначе — кандидат в новый токен.
- Типичные значения DistThr: 0.35–0.8. Выше — сильнее схлопывание (больше волн попадает в один глиф).

### 2.2. Полоса и частота

- **Один токен = одна полоса** (BandIdx). Волна из полосы B2 мержится только с токенами из B2 (или с учётом правил для соседних полос на границе).
- **Частота**: допуск по частоте (BandFreqToleranceHz по полосе или ratio). Слишком далёкая по частоте волна не мержится в этот токен (создаётся новый или отбрасывается).
- **Соседние полосы** (например B2 и B3): merge разрешён только если частота у границы полос и форма **очень** похожа (строже порог по расстоянию).

### 2.3. Дополнительно при merge

- **RatioXY, RatioXZ** (соотношения осей): при fallback-сравнении слишком сильное расхождение по |log(new/ref)| может запретить merge.
- **ShapeSignature** (топология, zero-cross, симметрия): при полном совпадении сигнатуры merge по форме с DistThr; при несовпадении — только при очень малом расстоянии (fallback).

Итог: **мерж = та же полоса + близкая форма (ShapeDistance < DistThr) + допустимая частота (и при необходимости соотношения осей)**.

---

## 3. Что происходит при merge и при новом токене

- **Merge**: у выбранного паттерна увеличивается **Occurrences**, обновляется **LastSeenTs**, эталон формы (GlyphShape) может слегка обновляться (EMA), обновляются метаданные (Amp, RatioXY/XZ, Confidence и т.д.).
- **Новый токен**: в хранилище (PatternStore) добавляется новый паттерн с **Occurrences=1**, **Captured** и **LastSeenTs** = текущее время.

---

## 4. Порядок отображения: «топ»

- На экране ALPHABET и в снапшоте для GUI токены показываются в порядке **ListOrderedByTop()**:
  1. Сначала по **Occurrences** (убывание): чем чаще токен встречался, тем выше.
  2. При равных Occurrences — по **LastSeenTs** (убывание): недавно обновлённые выше.

Так что «топ» — это самые частые и самые свежие глифы сверху.

---

## 5. Удаление по времени (TTL)

- У каждого паттерна есть **LastSeenTs** (время последнего merge или последнего появления).
- **Glyph TTL** (в интерфейсе «TTL 0 / 30s / 60s / 120s»): если **текущее время − LastSeenTs > TTL** (в секундах), паттерн **удаляется** из алфавита.
- **TTL = 0** означает «не удалять по возрасту».
- Проверка выполняется периодически (раз в несколько секунд) по всем сенсорам.

Итог: редко появляющиеся или давно не обновлявшиеся глифы исчезают, алфавит остаётся актуальным.

---

## 6. Настройки в правом блоке (Энтропия / алфавит)

| Параметр | Влияние |
|----------|--------|
| **H_thr** | Порог остаточной энтропии при разложении окна (останов, когда остаток «шум»). |
| **minΔH** | Минимальное снижение энтропии, чтобы считать совпадение с токеном значимым. |
| **dist** | **DistThr** — порог расстояния по форме: ниже = строже (меньше merge), выше = больше схлопывание. |
| **x≥N** | В реакциях показывать только с числом появлений ≥ N. |
| **TTL Ns** | Удалять глифы, не обновлявшиеся N секунд. |

---

## 7. График «Токены × повторы (лог)»

Справа внизу выводится гистограмма:

- **По горизонтали** — интервалы числа появлений: **1**, **2–4**, **5–9**, **10–99**, **100+**.
- **По вертикали** — **сколько токенов** попало в этот интервал (высота столбца в **логарифмической** шкале).

Так видно: много ли одноразовых глифов (столбец «1»), сколько стабильно повторяющихся (столбцы 2–4, 5–9 и т.д.) и есть ли «чемпионы» (100+).
