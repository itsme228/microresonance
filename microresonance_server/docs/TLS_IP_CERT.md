# HTTPS: самоподписанный сертификат для LAN

Для VR и WebXR в локальной сети (192.168.1.x и т.п.) сервер использует **только самоподписанный** сертификат. Let's Encrypt не выдаёт сертификаты для приватных IP (до них нельзя достучаться с интернета для валидации).

## Запуск (по умолчанию HTTPS :443)

```bash
# Из папки server: только HTTPS :443 (VR подключается по wss/https к этому порту)
go run . -gpu

# На Linux/macOS порт 443 часто требует root:
sudo go run . -gpu
```

При первом запуске в `certs/` создаются `server.crt` и `server.key` с текущими адресами (127.0.0.1 и все IPv4 интерфейсов). Сертификат **копируется в ../vr/certs/server.crt** — Godot VR APK доверяет этому же сертификату (wss/https без предупреждений). В логе:

```
TLS: self-signed cert in certs (IPs: 127.0.0.1, 192.168.1.100)
TLS: cert copied to .../vr/certs/server.crt (for VR APK)
HTTPS :443 | VR: https://<ip>:443/vr | wss://<ip>:443/ws
```

Порядок: 1) Запустить сервер один раз из `server/` — cert скопируется в `vr/certs/`. 2) Экспортировать VR APK в Godot. 3) Запускать сервер при работе с Quest.

## Параметры

| Флаг | Описание |
|------|----------|
| `-https=` | Адрес HTTPS (`:443`, `:8443` и т.д.). Пусто = только HTTP. |
| `-tlsCert=` | Путь к своему сертификату (PEM). |
| `-tlsKey=` | Путь к ключу (PEM). |
| `-certDir=` | Каталог для авто-сертификата, по умолчанию `certs`. |

Если заданы `-tlsCert` и `-tlsKey`, используются они. Иначе создаётся/подставляется самоподписанный в `-certDir`.
