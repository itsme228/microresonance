# Архитектура нейросети для распознавания намерений по алфавиту глифов

Документ описывает проектирование модели для извлечения **намерения** из вибрационных данных, представленных как **алфавит глифов** (~200–300 токенов). Каждый глиф — устойчивый частотно-динамический паттерн; вход — не сырой сигнал, а последовательности изменения глифов во времени.

---

## 1. Данные на каждом временном шаге (50–100 мс)

### 1.1 Метаданные глифа (для каждого из ~200–300 глифов)

| Признак | Описание |
|--------|----------|
| `present` | 0/1 — активен ли глиф в этом кадре |
| `age_ms` | Время с последнего появления (растёт при отсутствии) |
| `duration_ms` | Длительность текущего/последнего сегмента |
| `freq_center`, `freq_low`, `freq_high` | Частота (Гц) |
| `amp`, `amp_range_low`, `amp_range_high` | Амплитуда и диапазон |
| `envelope_slope` | Наклон огибающей |
| `ratio_x`, `ratio_x2` | Отношения осей/моментов (для направления) |
| `confidence` | Уверенность детектора |
| `occurrences` | Сколько раз глиф уже встречался |
| `shape_sig` | (T, E, A, M) — топология, envelope, асимметрия, модуляция |
| `channel` / `band` | Номер канала/бина |

**Важно:** Направление не равно знаку колебания (HF sign игнорируется). Направление закодировано в:
- распределении энергии по осям (X/Y/Z),
- фазовых сдвигах между осями,
- эллипсности и вращении траектории за цикл.

### 1.2 Cycle-patch (если `present=1`)

- **3-осевой сигнал (x, y, z) + combined** в виде **cycle-patch**: окно 2–3 периода глифа, ресэмплированное до фиксированной длины (например 128 точек).
- Цель: сохранить фазу, межосевые отношения и геометрию движения без зависимости от знака синуса.
- Если глиф не активен: передаётся последнее известное состояние + растущий `age_ms`.

---

## 2. Принципы архитектуры

- **Кормить все глифы** (~200–300), без top-K отсечения.
- **Per-glyph память**: каждый глиф — отдельный процесс во времени (своя временная линия).
- **Cross-glyph взаимодействие**: обмен информацией между глифами для извлечения намерения.
- **Combined** — грубая сцена; **3-осевой (x,y,z)** — тонкая векторная динамика и направление.
- Только числа, без визуализации в модели.

---

## 3. Общая схема архитектуры

```
                    ┌─────────────────────────────────────────────────────────┐
                    │                  INPUT (каждый тик 50–100 ms)            │
                    │  Для каждого глифа g ∈ [1..G]:                           │
                    │    • meta_g: [present, age_ms, duration_ms, freq_*,      │
                    │               amp_*, envelope_slope, ratio_*, confidence,  │
                    │               occurrences, shape_sig, channel]          │
                    │    • cycle_g: [128]×4 (x,y,z,combined) или last + mask   │
                    └─────────────────────────────────────────────────────────┘
                                              │
          ┌───────────────────────────────────┼───────────────────────────────────┐
          ▼                                   ▼                                   ▼
┌─────────────────────┐           ┌─────────────────────┐           ┌─────────────────────┐
│  METADATA BRANCH    │           │  CYCLE-PATCH BRANCH │           │  AGE/ABSENCE       │
│  (все глифы)        │           │  (все глифы)        │           │  (все глифы)       │
│  MLP(meta_g) → d_m  │           │  CNN1d(cycle_g) → d_c│           │  age_embed(age_ms)  │
│  или small TCN     │           │  + optional x,y,z   │           │  + present mask     │
│  G × d_m            │           │  separate streams    │           │  G × d_a            │
└──────────┬──────────┘           └──────────┬──────────┘           └──────────┬──────────┘
           │                                 │                                 │
           └─────────────────────────────────┼─────────────────────────────────┘
                                             ▼
                              ┌──────────────────────────────┐
                              │  PER-GLYPH FUSION            │
                              │  concat(meta_emb, cycle_emb,  │
                              │        age_emb) → d_g         │
                              │  Linear: d_g → d_h (e.g. 64)  │
                              │  G × d_h                      │
                              └──────────────┬───────────────┘
                                             │
                                             ▼
                              ┌──────────────────────────────┐
                              │  PER-GLYPH TEMPORAL (память) │
                              │  Для каждого глифа отдельно: │
                              │  GRU/LSTM/TCN(d_h, d_h)      │
                              │  Вход: вектор глифа в t      │
                              │  Выход: state_g(t)           │
                              │  G × d_h — «жизнь» глифа     │
                              └──────────────┬───────────────┘
                                             │
                                             ▼
                              ┌──────────────────────────────┐
                              │  CROSS-GLYPH (взаимодействие)│
                              │  Transformer / GNN / MHA     │
                              │  Query/Key/Value из state_g   │
                              │  Или: Dense(G×d_h → d_cross) │
                              │  Цель: композиция глифов     │
                              │  → context vector d_c        │
                              └──────────────┬───────────────┘
                                             │
                                             ▼
                              ┌──────────────────────────────┐
                              │  INTENTION EMBEDDING         │
                              │  Aggregation (mean/max/     │
                              │  attention) + MLP             │
                              │  → intention_emb [d_int]      │
                              └──────────────┬───────────────┘
                                             │
                                             ▼
                              ┌──────────────────────────────┐
                              │  HEAD (задача)               │
                              │  Класс намерения / регрессия │
                              │  Linear(d_int → n_classes)    │
                              └──────────────────────────────┘
```

## 4. Слои и потоки по шагам

### 4.1 Вход: метаданные

- **Форма:** на каждый тик — тензор `[G, F_meta]`, где G ≈ 200–300, F_meta — число скалярных признаков (present, age_ms, duration_ms, freq_center, …).
- **Обработка:** небольшой MLP по каждому глифу независимо: `[F_meta] → d_m` (например d_m=32). Либо лёгкий TCN по времени по каждому глифу, чтобы сгладить метаданные.
- **Зачем:** дать модели статическую и низкочастотную информацию о глифе (частота, амплитуда, уверенность, форма по shape_sig), не перегружая cycle-patch.

### 4.2 Вход: cycle-patch

- **Форма:** при `present=1` — патч длины 128 по 4 каналам (x, y, z, combined); при `present=0` — последний сохранённый патч + маска отсутствия (или нули + маска).
- **Обработка:**
  - **Combined:** 1D CNN (или маленький ResNet1d) → embedding размера d_comb (например 32). Грубая сцена.
  - **X, Y, Z отдельно:** общая 1D CNN с раздельными каналами на входе (или 3 ветки с shared weights), затем concat → d_xyz (например 32). Это сохраняет межосевые отношения и фазовые сдвиги → **направленная динамика**.
- **Объединение:** concat(d_comb, d_xyz) → d_c (например 64), или слой, который явно моделирует соотношения осей (эллипсность, фазы).
- **Зачем:** фаза и геометрия траектории (x,y,z) не теряются при ресэмплинге в 128 точек; знак синуса не используется как признак направления — направление в распределении энергии и фазе между осями.

### 4.3 Вход: age / absence

- **age_ms:** кодировать как embedding или log(1 + age_ms) с последующим Linear. При длительном отсутствии эмбеддинг должен отличаться (глиф «остыл»).
- **present:** бинарная маска; можно умножить ею выход cycle-patch (если нет патча — нулевой вклад cycle-ветки) и подать age как единственный сигнал «когда последний раз был активен».
- **Зачем:** модель видит и активные глифы, и их «жизнь» между появлениями — последовательность это жизнь каждого глифа во времени, а не очередь событий.

### 4.4 Per-glyph память (временная ось по каждому глифу)

- **Идея:** для каждого глифа g свой рекуррентный (или TCN) блок. Вход на шаге t — сконкатенированный вектор глифа (meta_emb, cycle_emb, age_emb) размерности d_g.
- **Варианты:**
  - **GRU/LSTM:** `state_g(t) = RNN_g(embed_g(t), state_g(t-1))`. Память по каждому глифу отдельно.
  - **TCN (temporal convolution):** скользящее окно по времени по каждому глифу; меньше параметров, параллелизм по времени.
- **Выход:** `[G, d_h]` — вектор состояния каждого глифа в момент t. Это и есть «жизнь» глифа во времени.
- **Зачем:** последовательность = эволюция каждого из G глифов; без per-glyph памяти модель видела бы только срезы «кто сейчас активен», теряя историю включений/выключений и длительности.

### 4.5 Cross-glyph взаимодействие

- **Идея:** намерение определяется комбинацией активных глифов и их динамики. Нужен обмен информацией между глифами.
- **Варианты:**
  - **Transformer:** состояния `state_g` как последовательность длины G; self-attention даёт взаимодействие. Positional encoding можно заменить на id глифа или оставить без позиции (глифы не упорядочены).
  - **Multi-Head Attention** по оси глифов: Query, Key, Value из `state_g` → контекстный вектор на каждый глиф, затем агрегация.
  - **GNN:** узлы = глифы, рёбра по сходству (частота, полоса) или полный граф; 1–2 слоя message passing.
- **Выход:** обновлённые представления глифов и/или один глобальный контекстный вектор `context [d_c]`.
- **Зачем:** намерение не есть «один глиф», а композиция; cross-glyph слой собирает эту композицию.

### 4.6 Embedding намерения

- Из cross-glyph выхода: либо один вектор `context`, либо агрегация по глифам (mean, max, или attention-weighted sum по `state_g`).
- Дополнительно MLP: `context → d_int` (например d_int=128).
- Этот вектор — **embedding намерения**: компактное представление комбинации глифов и их динамики за окно.

### 4.7 Голова (head)

- Классификация: `Linear(d_int → n_classes)` + softmax.
- Или регрессия/многозадачность (несколько намерений, уверенность и т.д.).

## 5. Как не терять направленную динамику при множестве вершин/низов

- **Не опираться на знак синуса** — в признаках и cycle-patch использовать нормализованную по фазе форму (например 0…1 по фазе цикла), либо magnitude envelope по осям.
- **Явные признаки направления:** ratio_x, ratio_x2, shape_sig; в cycle-patch — **три отдельные оси x, y, z** с общей временной осью (128 точек), чтобы фаза между осями сохранялась. Тогда эллипсность и ориентация эллипса = направление.
- **Слой для осей:** после CNN по x,y,z — слой, который комбинирует их (например, предсказ эллипса: полуоси и угол), или просто concat + MLP, чтобы модель сама выучила соотношения.
- **Длина патча 2–3 периода:** достаточно для фазы и геометрии; ресэмплинг в 128 точек сохраняет относительные фазы между осями.

## 6. Рекомендации по размерам и типам сетей

| Компонент | Рекомендация | Размеры (пример) |
|-----------|--------------|-------------------|
| Метаданные | MLP 1–2 слоя | F_meta → 32 → d_m=32 |
| Cycle-patch | 1D CNN, kernel 5–7, 2–3 блока | 128×4 → 64 → 32 → d_c=64 (combined+xyz) |
| Age/absence | Embedding или Linear(log(1+age)) | d_a=16 |
| Per-glyph fusion | Linear | (d_m+d_c+d_a) → d_h=64 |
| Per-glyph temporal | **GRU** (проще) или **TCN** (быстрее) | d_h=64, 1–2 слоя |
| Cross-glyph | **Transformer** (2–4 головы, 1–2 слоя) или MHA | d_h=64, d_c=64 |
| Intention | Mean/Max + MLP | d_c → d_int=128 |
| Head | Linear | d_int → n_classes |

- **GRU** — хороший баланс память/параметры для per-glyph последовательности.
- **TCN** — если важна скорость и длинное окно; каузальные свёртки по времени по каждому глифу.
- **Transformer** для cross-glyph — естественная модель «все глифы смотрят друг на друга»; без top-K все глифы участвуют в attention.

## 7. Как подавать данные в обучении

- **Мини-батч:** (B, T, G, …) — B батч, T временных шагов (окно, например 50 кадров по 50 ms = 2.5 s), G глифов.
- **Мета:** (B, T, G, F_meta).
- **Cycle-patch:** (B, T, G, 128, 4) — при отсутствии глифа использовать последний патч или нули и маску; маска (B, T, G) для loss.
- **Целевой метки:** на уровне окна T (одно намерение на окно) или при необходимости на каждый t (тогда нужна разметка по времени).

---

## 8. Self-supervised идеи (опционально)

- **Предсказание следующего глифа/следующего состояния:** по state_g(t) предсказать meta или краткий код следующего кадра для части глифов — заставляет модель учить динамику.
- **Контраст по окнам:** два перекрывающихся окна одного сегмента — близко в пространстве эмбеддингов; два разных действий — далеко.
- **Маскирование глифов:** замаскировать случайные глифы по времени и восстанавливать их мета или cycle из контекста (cross-glyph + остальные глифы).
- **Предсказание продолжительности удержания:** по state_g предсказать duration_ms или age_ms на следующем шаге — регрессия по времени жизни глифа.

---

## 9. Кратко

- **Вход:** все глифы каждый тик: метаданные, cycle-patch (x,y,z,combined), age/absence.
- **Per-glyph память:** GRU/TCN по времени для каждого глифа → «жизнь» глифа.
- **Cross-glyph:** Transformer/MHA по глифам → композиция.
- **Направление:** в мета (ratio_*, shape_sig) и в 3-осевом cycle-patch (фаза и энергия по осям), без использования знака HF.
- **Embedding намерения:** агрегация выхода cross-glyph + MLP → голова классификации/регрессии.
- Упрощения вида «только top-K глифов» или «FFT как основной признак» не используются; семантика глифов, их жизнь во времени и направленная динамика сохраняются в архитектуре.
